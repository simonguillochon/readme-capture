# 2. Besoin client

## Demande initiale

Il est nécessaire pour Simon que l'utilisatrice puisse enregistrer, depuis son navigateur, les informations, extraits et synthèse d'un contenu consommé en veille directement dans la base Notion Readme center, afin de supprimer la recopie manuelle de texte entre la page lue et Notion.

## Reformulation

Chaque semaine, l'utilisatrice consomme du contenu sur Gmail, LinkedIn, X et d'autres sites. Aujourd'hui, elle recopie à la main des passages, puis crée un item dans Readme center et résume ses notes en une phrase dans la propriété Description.

Une extension Firefox, utilisée dans le navigateur Zen, affiche un panneau latéral que l'utilisatrice ouvre uniquement quand elle fait sa veille. Depuis ce panneau, elle crée l'item avec des métadonnées pré-remplies à partir de la page lue. Elle y ajoute ensuite des extraits sélectionnés dans la page, rangés sous des sections, puis rédige la description. Tout est écrit dans Notion au fil de l'eau.

## Bénéfice métier attendu

La veille hebdomadaire alimente Readme center sans copier-coller entre la page lue et Notion. Chaque item est complet et homogène : URL propre, métadonnées renseignées, extraits structurés en citations. Quand il est connu, le profil LinkedIn de l'auteur permet à la publication hebdomadaire automatisée de la curation sur LinkedIn de mentionner l'auteur. Le panneau ne s'affiche que pendant les sessions de veille et ne gêne pas la navigation quotidienne.

# 3. Solution convenue

## Description fonctionnelle

L'extension affiche un panneau latéral dans Zen. Un clic sur le bouton de l'extension, dans la barre d'URL, ouvre ou ferme le panneau. Quand le panneau est fermé, l'extension n'agit pas. Elle gère une seule capture à la fois, qui va de la création d'un item Readme center jusqu'au bouton « Terminer ».

**Métadonnées de l'item.** Tous les champs sont obligatoires pour activer le bouton « Ajouter », sauf « LinkedIn de l'auteur ».

| Champ du panneau | Propriété Notion | Remplissage |
| --- | --- | --- |
| Titre | Title | Pré-rempli depuis la balise `og:title`, sinon depuis le titre de l'onglet. Pour un post LinkedIn ou X, pré-rempli avec la première phrase du post. Vide si rien n'est trouvé. |
| URL | URL | URL de l'onglet, nettoyée : tout ce qui suit le `?` est supprimé, sauf exception listée dans le code. Seule exception initiale : `youtube.com/watch` conserve `v`. |
| Auteur | Source | Pré-rempli depuis les balises `author` ou `article:author`, puis les données structurées de la page. Pour un post LinkedIn ou X, pré-rempli avec l'auteur du post. Vide si rien n'est trouvé. |
| LinkedIn de l'auteur | LinkedIn auteur | Facultatif. Pré-rempli avec le profil LinkedIn déclaré pour l'auteur par la page (balise `article:author`, données structurées) ou, pour un post LinkedIn, avec le profil de son auteur. Vide sinon. Seuls les profils `linkedin.com/in/…` sont acceptés. |
| Langue | Icône de la page | Choix manuel entre 🇫🇷 français, 🇬🇧 anglais et 🇪🇸 espagnol. Aucune valeur par défaut. |
| Thèmes | Theme | Multi-sélection manuelle, au moins un thème. La liste est lue dans la base Notion à l'ouverture du panneau. |
| *(non affiché)* | Date | Date de capture, renseignée automatiquement. |

Tous les champs affichés restent modifiables. La propriété Type n'est pas renseignée.

**Création de l'item.** Le bouton « Ajouter » crée l'item dans Readme center. Si l'URL existe déjà dans la base, un avertissement s'affiche sans bloquer la création.

**Modification après création.** Les métadonnées restent modifiables pendant toute la capture, mais ne sont plus jamais pré-remplies automatiquement. Un bouton « Enregistrer les modifications » apparaît dès qu'un champ diffère des valeurs enregistrées et envoie les modifications à Notion. Aucune détection de doublon n'a lieu après la création, même si l'URL modifiée existe déjà dans la base. Une fois l'item créé, et après chaque enregistrement des modifications, le formulaire se replie en une ligne affichant le titre ; un clic le déplie.

**Extraits.**

- Le panneau affiche un aperçu de la sélection en cours dans la page.
- Après son ajout, l'extrait est surligné en entier dans la page lue, sur fond vermillon pâle, jusqu'à la fermeture du panneau ou au rechargement de la page. Le surlignage ne modifie pas le contenu de la page.
- L'utilisatrice choisit une section, puis clique sur « Ajouter l'extrait ».
- Le menu Section propose les sections déjà créées pour l'item, « + Nouvelle section… » et « Sans section ». La dernière section utilisée est pré-sélectionnée.
- « + Nouvelle section… » ouvre un champ pré-rempli avec le titre de la page le plus proche de la sélection, ainsi qu'un choix de niveau H1, H2 ou H3, H1 par défaut.
- Dans le corps de la page Notion, chaque extrait est écrit en citation sous le titre de sa section. Un extrait sans section est écrit en citation seule.
- Les extraits ajoutés restent listés dans le panneau. L'utilisatrice peut les modifier, les déplacer vers une autre section ou les supprimer, sans confirmation, et le changement est répercuté dans Notion. Une section qui n'a plus d'extrait disparaît, titre compris.
- L'ajout d'extraits fonctionne depuis n'importe quel onglet, sans avertissement.

**Description.** Une fois l'item créé, le panneau propose, entre les informations de l'item et les extraits, un champ texte pour la phrase de synthèse, limité à 2000 caractères, avec un compteur. Le bouton d'enregistrement, affiché quand le texte diffère de la description enregistrée, écrit le texte dans la propriété Description. L'utilisatrice peut enregistrer plusieurs fois, et chaque enregistrement remplace le précédent. Enregistrer un champ vide efface la description.

**Fin et reprise de capture.** La capture en cours est conservée dans le stockage local de l'extension. Fermer le panneau ou le navigateur ne la perd pas, et elle reprend à la réouverture. Le bouton « Terminer » remet le panneau à zéro pour une nouvelle capture, sans le fermer et sans appel à Notion. S'il reste des modifications non enregistrées, il demande une confirmation. Une capture qui concerne une autre base que celle configurée est abandonnée à la réouverture.

**Configuration.** Une page d'options reçoit le jeton d'une intégration Notion interne et l'URL de la base Readme center, dont l'extension extrait l'identifiant. Ces valeurs sont stockées localement et ne figurent jamais dans le code.

**Erreurs.** En cas d'échec, rien de ce que l'utilisatrice a saisi n'est perdu. Le message indique la cause la plus probable :

| Cas | Message | Action proposée |
| --- | --- | --- |
| Pas de réseau | Connexion impossible | Réessayer |
| Jeton invalide ou révoqué | Jeton Notion invalide | Lien vers les options |
| Base introuvable ou non partagée avec l'intégration | Base inaccessible | Lien vers les options |
| Item supprimé ou archivé dans Notion | Item introuvable dans Notion | Terminer la capture |
| Structure de la base modifiée | La base Notion a changé | Recharger les thèmes, Réessayer |
| Trop de requêtes | Notion limite les appels | Réessai automatique après le délai indiqué par Notion, 1 seconde s'il n'en indique pas, 3 réessais au maximum, puis Réessayer |
| Notion indisponible | Notion ne répond pas | Réessayer |
| Page illisible (pages internes du navigateur, visionneuse PDF…) | Sélection impossible sur cette page | Aucune |

Lors de la vérification de la connexion, toute autre réponse d'erreur de Notion (4xx) ou une réponse illisible affiche « Base inaccessible ». Sur une modification de l'item, de ses extraits ou de sa description, toute réponse 400 ou 404 affiche « Item introuvable dans Notion ».

« Réessayer » relance l'action échouée avec les mêmes données. Pour la lecture des thèmes, il prend la forme « Recharger les thèmes ». « Terminer la capture » termine sans confirmation ; il n'est pas proposé pour un extrait introuvable, que l'utilisatrice peut supprimer de la liste. Après une correction dans la page d'options, le panneau utilise la nouvelle configuration sans être rouvert.

## Parcours utilisateur

1. L'utilisatrice ouvre un contenu dans un onglet. Pour un post LinkedIn ou X, elle l'ouvre dans sa propre page, ou colle plus tard son URL dans le champ.
2. Elle ouvre le panneau latéral en cliquant sur le bouton de l'extension dans la barre d'URL. Titre, URL nettoyée et auteur sont pré-remplis.
3. Elle ajuste les champs, choisit la langue et au moins un thème, puis clique sur « Ajouter ». L'item est créé dans Readme center, avec un avertissement si l'URL existe déjà.
4. Elle sélectionne un passage dans la page. L'aperçu apparaît dans le panneau.
5. Elle choisit une section existante, en crée une nouvelle ou choisit « Sans section », puis clique sur « Ajouter l'extrait ». La citation est écrite dans la page Notion.
6. Elle répète les étapes 4 et 5. Si besoin, elle modifie ou supprime un extrait, ou corrige une métadonnée puis clique sur « Enregistrer les modifications ».
7. Elle rédige sa phrase de synthèse et l'enregistre dans Description.
8. Elle clique sur « Terminer ». Le panneau est prêt pour la capture suivante.

## Maquettes

Aucune maquette à date. Les composants de l'interface sont codés en Vue et respectent le design system [ds-editorial-tech](https://github.com/simonguillochon/ds-editorial-tech), qui fait foi.

# 4. Périmètre

## Hors scope

- Génération du résumé par IA (API Claude, modèle Sonnet) — *Raison : tester l'utilité de l'extension avant d'engager un coût d'usage. Prévue en v2, elle pré-remplira le champ Description.*
- Déduction automatique du lien permanent d'un post depuis un fil LinkedIn ou X — *Raison : trop fragile, le code HTML de ces sites change souvent.*
- Renommage, changement de niveau ou suppression explicite d'une section depuis le panneau — *Raison : ces corrections se font dans Notion. Une section disparaît seulement avec son dernier extrait.*
- Écran de gestion des exceptions de nettoyage d'URL — *Raison : la liste est écrite dans le code, l'enrichir passe par une évolution.*
- Langues autres que le français, l'anglais et l'espagnol.
- Détection automatique de la langue.
- Propriété Type de la base — *Raison : jugée inutile, sa suppression de la base est prévue.*
- Traitement spécifique des e-mails Gmail — *Raison : les newsletters sont lues sur leur plateforme d'origine, comme Substack.*
- Captures simultanées de plusieurs items.
- Enregistrement automatique des métadonnées modifiées après création.
- Détection de doublon après la création de l'item — *Raison : l'avertissement n'est utile qu'avant de créer l'item.*
- Raccourci clavier pour ajouter un extrait — *Raison : idée à explorer à l'usage.*
- Restriction de l'ajout d'extraits à l'onglet de l'item, et avertissement quand l'onglet actif n'est pas celui de l'item — *Raison : jugés superflus en v1, idée à explorer à l'usage.*
- Tests e2e de l'extension — *Raison : la faisabilité avec Karate dans Firefox n'est pas démontrée. Prévus dans une version ultérieure, à partir des scénarios OpenSpec.*
- Publication publique sur addons.mozilla.org — *Raison : usage personnel uniquement.*

* Synchronisation dans le panneau des modifications faites directement dans Notion pendant une capture — *Raison : non nécessaire en v1. L'erreur « Item introuvable dans Notion » s'affiche seulement si l'utilisatrice modifie ensuite depuis le panneau un extrait supprimé dans Notion.*

## Hypothèses

**Technique**

- Extension Firefox en Manifest V3, construite avec WXT, Vue 3 et TypeScript.
- Interface en Tailwind. Les valeurs du design system ds-editorial-tech sont transcrites dans la configuration Tailwind. Aucun fichier du dépôt du DS n'est copié ni importé.
- Les composants sont codés en Vue selon la spec des atomes du DS. Les polices du DS sont intégrées à l'extension.
- Le panneau suit le mode clair ou sombre du système.
- Toute déviation au DS, ou tout composant non spécifié dans le DS, est soumis à l'utilisatrice avant implémentation. Écart validé : le compteur de caractères de la description.
- Les composants suivent la version 1.13 du DS depuis l'US-08, cibles de 44 px comprises.
- Aucune base de données : jeton, URL de la base et capture en cours sont dans le stockage local de l'extension. Seule l'API Notion reçoit des données.
- La connexion à Notion passe par une intégration interne, partagée avec la base Readme center.
- Le dépôt GitHub est public. Il ne contient aucun jeton ni identifiant personnel.
- Tests unitaires avec Vitest. Tests de contrat de l'API Notion avec Karate, sur une base de test dédiée.
- Pendant le développement, l'extension est chargée en temporaire. Pour l'usage réel, elle est signée en « non listée » sur addons.mozilla.org, à partir de la version 1.0.0.
- Le manifeste déclare que l'extension ne collecte aucune donnée (`data_collection_permissions` : `none`) : la configuration reste dans le stockage local, et les contenus capturés ne sont envoyés qu'à la base Notion de l'utilisatrice, à sa demande.

* Les tests de contrat Karate s'exécutent sur la base Readme center (tests), de même structure que Readme center, créée vide et partagée avec la même intégration. Les tests créent eux-mêmes les items dont ils ont besoin.

- Zen affiche le panneau latéral natif des extensions Firefox. Vérifié le 25/10/2026 avec l'extension Sidebery.
- La mise en place du socle technique fait partie des premières tâches de l'US-01 : initialisation du projet, puis vérification du Gherkin français avec `openspec validate`. Claude Code s'arrête ensuite pour un compte rendu avant de poursuivre l'US.

**Méthode**

- Chaque US est rédigée en change OpenSpec, sans perte d'information par rapport au template d'US SCUB.
  - `proposal.md` porte l'ID, l'epic, la priorité, la formulation « En tant que / Je souhaite / Afin de », l'objectif, les maquettes, la DoD et le lien vers ce PRD.
  - Les règles métier deviennent des exigences, les tests d'acceptation deviennent des scénarios en Gherkin français.
  - `design.md` porte les clés d'implémentation, `tasks.md` le plan d'implémentation.
- La Definition of Done SCUB est adaptée : tests unitaires Vitest passants, tests de contrat Karate passants quand l'US touche à l'API Notion, et `openspec validate` sans erreur.
- Claude Code implémente uniquement les tâches de `tasks.md`. Il s'arrête et pose la question dès qu'un point n'est pas couvert par les specs.
- La règle SCUB d'un maximum de 4 US par PRD est levée pour ce PRD, afin de garder des US précises.

* Les scénarios OpenSpec sont rédigés en Gherkin français (« ÉTANT DONNÉ QUE / LORSQUE / ALORS / ET »). Chaque exigence garde le mot-clé `SHALL` ou `MUST` en anglais, et les en-têtes de structure restent en anglais. Vérifié le 25/10/2026 avec `openspec validate --strict` (OpenSpec 1.15.0).
